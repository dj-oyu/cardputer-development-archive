# Exact transport attribute storage audit

Design-only investigation of completed `fox-v3-depth-bands`. No renderer, model, reference, device, public branch, PR or production source change. No owned-context or unfinished paged-BVH source consulted. Paging is not the selected direction.

## Result

Select **bit-exact vertex attribute interning**, independent of the existing indexed geometry BVH. All 40 already completed off/on snapshot fixtures contain 773 distinct referenced character attribute records; adding the existing floor placeholder gives **774 distinct 20-byte vertices**. Each fixture has 54 packets, 1163 serialized vertices and 1564 character triangles; transport adds two ground triangles. The Python inspection was independently checked through the completed C `co_read` / `co_pixel_vertex_at` / `co_triangle_at` implementation. Both agree for all 40 fixtures. This is read-only fixture analysis, not a fresh render or implemented compression result.

Suggested internal triangle record: three uint16 indices plus double_sided byte and one reserved byte, exactly 8 bytes. Fixture payload =774*20+1566*8=28008 bytes. With the unchanged 584-byte control-size allowance, predicted scene is **28592 bytes**, saving **72216 bytes** from100808. Actual new descriptors/alignment must be measured; this is not a compiled new scene size. For a deliberately separate dictionary and triangle array, payload requests would be15480 and12528 bytes, plus control/pointers. A combined representation should also fit below32768 for these fixtures if descriptor additions remain below4176 bytes. This does not imply the complete renderer fits a target heap.

Before fixture inspection, a valid upper bound from completed construction was1164 unique records:1163 character vertices plus one floor attribute value. That bound gives36392 bytes with the same584-byte allowance. The measured774 supersedes that conservative fixture bound, not the generic API bound.

Evidence artifacts: `SNAPSHOT_COUNTS.json` includes source paths and SHA256 for all40 files; `inspect_snapshots.py` is the exact-byte inspection; `verify_codec.c` and `CODEC_VERIFY.txt` provide independent existing-codec verification and host layout measurements. No source model was read to obtain these counts.

## Generic admission and worst case

At2048 triangles there can be6144 unique corners; all fit uint16 indices. Indexed storage worst case =122880 vertex bytes+16384 triangle bytes+584=139848, versus131656 legacy bytes:8192 additional bytes, exactly4 bytes per triangle. At1566 all-unique indexed cost is106488 versus100808, a6264-byte increase (4*n). No automatic benefit for arbitrary input. Break-even ignoring descriptor additions is U<=floor(56*n/20); at1566 this is4384 unique vertices.

Do not silently change the existing builder's accepted set or byte cap. Narrowest migration is an explicit opt-in builder with exact required-size reporting and explicit budget, leaving the legacy builder unchanged. An internal adaptive legacy fallback is another possibility, but must preserve all original admission decisions and the documented accounting API. The existing `bounce_scene_required_bytes(n)` is data-independent, while exact interned bytes depend on attributes; `harness/native_render_row.c:131` currently requires exact equality with scene bytes. Resolve this deliberately with an opt-in exact preflight/query or separately named bound, not by silently lying about actual bytes or relaxing max_bytes. Keep the262144 hard cap and all original validation. New-budget rejection must leave old scene unchanged.

Vertex equality should compare all20 bytes only after full original validation. Preserve mask bit identity including +0/-0; `==` is insufficient. Both front/back normals and both colors participate. Static assertions should confirm offsets mask12, a56516, b56518, size20. Distinct bit patterns that happen to render equally still remain distinct. Original sidedness remains per triangle. Ground placeholders are validated even though shading bypasses their material fields.

Construction can avoid a new large transient dictionary/hash table with bounded quadratic scans of earlier original corners, first counting unique values, then allocating exact-size owned storage and populating it. This adds build CPU work, not shader arithmetic; measure it. A faster hash map needs an explicitly accounted build-only allocation and collision-safe full-byte comparisons. Do not introduce a6144-record stack dictionary. Do not borrow caller input or freed model/snapshot memory.

## Ownership, failure atomicity, tests

- Preserve `bounce.c:35–48` validation order and statuses: pointers, sign, generations, ground values/range, count, limits, geometry generation, token monotonicity, light validation, double_sided<=1, zero padding, finite mask, each nonzero normal without INT16_MIN. Validate every input corner before compressing or skipping a duplicate. Input count zero/>2048 remains invalid. Rejection must not mutate source or old scene.
- Preserve original generations, geometry retain/release, old retained bindings and immutable owned lights/ground (`:23–24,45–55`). Build all storage and bind geometry before the single slot swap; unwind every successful allocation on each later failure. A failed scene retains neither partial dictionary nor geometry reference. Caller inputs may be inside the retained old scene, so old scene cannot be released until copies and commit finish.
- `owned()` at`:20`, `bounce_scene_overlaps()` at`:219`, constructor slot alias checks`:42–44`, binding checks`:54–55`, and evaluator guards`:160–174` must include every owned allocation if split, plus retained visibility. If one compact allocation remains, keep range accounting exact. Alias checks cannot treat aggregate bytes as one span when storage is split. Do not mutate budgets through an alias into dictionary/index/control storage.
- Tests already exist at `transport/test_bounce.c:26–40` for copy/poison lifetime, budget/result atomicity, generation and replacement; `transport/test_ground.c:16–19,25` for descriptor lifetime, generation and capacity; `floor-tests/test_floor.c:47–48` for retained floor scenes and invalid inputs. Extend rather than substitute these.
- Add adversarial exact-bit dictionaries: +0/-0 masks, one-bit normal/color differences, non-opposite normals, all-identical/all-unique corners, first/last valid uint16 indices, generic max6144 unique, and inputs where duplicates precede an invalid last corner. Verify old tokens cannot regress; budget boundary-1/exact; every allocation failure stage; all alias spans including index/dictionary interiors and span crossing; poisoned inputs; retained old/new scenes; identical result/counter/budget outcomes against legacy.
- Keep shader arithmetic source expressions/order intact and compare outputs bitwise in synthetic tests before any later separately authorized actual evaluation. Measure .su call-chain totals and code size. Existing background chain4080/4096 has only16 bytes headroom; no stack safety can be inferred from storage savings. Do not reconstruct a64-byte triangle on shader stack.

## Smaller alternatives, not selected

Removing only validated triangle padding by storing60-byte corner triples plus one byte sidedness saves4698 bytes for1566 (96110 total with584 allowance). Bit-packing sidedness saves6068 (94740). Both retain a large allocation and provide much less value than measured exact interning. Dropping back normals on presumed antipodality, reducing float precision, changing mask representation, or releasing transport attributes during rendering is not generally exact. Transport attributes remain live for later first-hit material lookup. Paging would reduce largest allocation but not payload and requires expanded alias/rollback machinery; it is not recommended for this next prototype.

No remaining read-only blocker. Implementation, new-stack proof and parity validation remain future work.
