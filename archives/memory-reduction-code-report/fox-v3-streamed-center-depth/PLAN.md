# Streamed center depth: proposed contract before implementation

Base: completed fox-v3-cached-profile-renderer; all 162 frozen files verified before copying. Old roots immutable. No actual frames, device, SDK, public repository or PR work.

New private API retains full private RGB and cached profile. KsnStreamDepth contains strip pointer/exact7680 bytes, pending pointer/exact960 bytes, and optional capture pointer/exact129600 bytes (NULL/0 in production). Frozen before any overlap callbacks; original descriptor and admitted spans stay live through return. Callbacks must not free or reallocate original admitted storage. New KsnStreamDepthReport contains pending_copy_floats, capture_copy_floats, and complete; host size expected24 bytes. Old full-depth APIs unchanged.

The center strip is still 8 rows and uses identical float arithmetic/ties. After each successful strip, diagnostic mode copies its depth once into the capture span. Pending previous HDR/IDs/depth are consumed at the exact old pending-row point after the next strip shading. At16 boundaries, copy last current depth row to pending after the existing HDR pending copy. No new shader/profile/composition callback; no output publication. Quarter winner depth is independent and untouched, and center scratch is not reused by quarter code.

Admission: core14 slots including optional capture, 13live production/14live diagnostic, charge14+live*(live-1)/2+6*live =170/189. Adapter28slots including optional capture, 27live production/28live diagnostic, successful pair charges351/378 OFF and378/406 ON. All admitted spans retain checks against snapshot, identities, mutable context/reports, retained scenes, static encoded profile asset, cache, descriptors and optional world work. The new report is initialized only after admission. Core report completion is not adapter acceptance.

New copy categories are separate sidecar counters with fixed caps3840 pending float copies (15360bytes),32400 diagnostic float copies (129600bytes). Existing RH_COPY remains HDR-only. New copy guard calls count in RH_GUARDS. Sum existing producer work plus new copies remains under unchanged637599 cap or fails; no category cap rises. Capture is direct memcpy, not an opaque sink, so there is no sink callback lifetime/failure surface; allocation/write failures stay harness-level and no completion marker is accepted.
