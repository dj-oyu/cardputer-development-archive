## Bit-exact bound construction

Do not replace fmin/fmax by comparisons or assume a signed-zero tie convention. Preserve the existing build_bounds function's exact nested calls fmin(p0,fmin(p1,p2)) and fmax(p0,fmax(p1,p2)), and preserve the node's original triangle scan order. For each computed triangle bound, select one of that triangle's three original vertex IDs by comparing the complete object representation of the computed double with the source coordinate via memcpy/memcmp. Finite validation already precedes scene allocation and rejects NaNs, infinities and magnitudes above 1e50. Every finite min/max result must be bit-identical to an operand on the supported binary64 build, including signed zeros; explicit tests verify this premise. If no source matches, reject construction atomically rather than publish a bad index.

Revision after first synthetic test (no actuals): The initial per-merge witness helper failed O2 signed-zero exactness because GCC changed fmin call operand order relative to the baseline. It is rejected, not normalized. Instead use a construction-local six-double bounds struct and the original complete build_bounds + node accumulation loop. Only after that original accumulation, scan the node's triangle membership for each final bound and save the first bit-identical vertex witness. This is at most18*count bit comparisons per node, O(sum of node triangle counts), not O(n squared). Construction-only scratch is measured including recursive depth; there is no query scratch or persistent double cache. Failure to find any witness rejects the unpublished scene atomically. Independent O0/O2/sanitized canonical-node tests must prove exactness; if compiler operand behavior still differs, stop and report rather than choose a signed-zero policy.
Select split axis by exactly the same subtraction and greater-than expression, gathering the same double bits through node IDs. Do not change build_center arithmetic, sort order, recursion or work allocation. The preserved original bound calculation and baseline differential test are the authority; numeric equality alone is insufficient.
