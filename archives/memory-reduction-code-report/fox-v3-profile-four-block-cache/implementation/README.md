# Independent snapshot-validated fixed4 profile cache

This is a host research prototype, not integrated into a renderer or firmware and not demonstrated on hardware. No frozen prior source is edited. Compile block_cache.c with FAST_BITS=0 for comparison with the prior gather decoder, and candidate_profile.c against fox-v3-lossless-profile-lut/profile/private/profile_data.h. The profile's arithmetic is unchanged.

## Frozen API and lifetime contract

Caller owns one agx_block_cache, initialized by agx_cache_init (or agx_cache_bind directly). No allocation, mutable global, thread safety, ownership transfer, or hidden singleton. Fields are internal implementation state despite their public C layout: caller must not corrupt, modify or concurrently share them. Counters may be read. clear discards pointer, entries and counters. bind always discards prior state, including same pointer/length, and validates header plus all index offset bounds/monotonicity. It does not decode all records. Ordinary failed bind leaves unbound. Exception: bind with blob/context overlap returns failure without changing either, preserving the old binding; callers must check its result. A null context cannot be changed.

The blob is borrowed: it must be live, readable at the advertised size, and stable during each call. Unbind before releasing storage; explicitly bind after logical asset replacement even when its address is reused. No UAF or actual asset identity detection is promised. For defensive between-call mutation handling, every fetch checks the header and selected offsets; a hit additionally compares the selected encoded record bytes with a retained bounded snapshot. Changed selected bytes invalidate then decode from current live storage. A malformed selected record fails. Unselected payload corruption is not detected until accessed, and unselected index changes are not fully rescanned until bind. A restored identical record is valid again. These checks neither authorize concurrent mutation nor remove the lifetime obligation.

fetch4 returns 1 only for complete success, 0 for failure. profile_eval returns existing status 0/1/2, with 3 for decode failure. Both preserve public output on failure. Successful/failed calls may alter cache entries/counters internally; partially decoded entries never become valid. No output or index region may overlap writable cache; output may not overlap blob. Indices/output alias is supported by staging. Profile input/output alias is supported because all input reads precede output commit. Alias-invalid profile calls return INVALID. Binding overlap is rejected before any reads or writes.

Four entries use exact LRU ages, decoded 3x64 uint16 values and <=396 encoded bytes per entry. Unused tail values and bytes are never read. Header/index validation and snapshot comparison are included in the candidate operation, not omitted from timings. Hits count per requested vertex, not per unique block or per profile; misses count attempted decodes, including malformed attempts; invalidations count changed cached records after valid offsets. Four same-block vertices produce one miss and three hits on a cold cache. No fullblob hashing occurs per pixel. Static profile_data.h is private generated immutable data and is not copied here.

Counter uint64 overflow wraps modulo 2^64 and does not affect eviction or output. Cache memory must stay initialized for all operations other than init/bind. All passed buffers must be valid at their advertised size and properly aligned for their declared C type. Physical costs need target measurement; host struct/stack/object sizes are not embedded firmware RAM/flash/stack proof.
