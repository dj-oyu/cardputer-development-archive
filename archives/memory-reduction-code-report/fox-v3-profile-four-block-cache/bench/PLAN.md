# Frozen fixed-four-block cache ordered host benchmark

Arms: original raw uint16 profile; frozen four-fetch compressed baseline; frozen stateless gather without FAST_BITS (previous best); new caller-owned fixed-four-block profile cache. Original arm sources and all prior files remain unchanged. No rejected owned-ray context, device changes, public deployment, rendering, input modification, or raw inputs in a shareable bundle.

Input: verify every one of the 87 pins in fox-v3-lossless-profile-lut/profile/INPUTS.json before and after. Read all 40 frames in the original listed order, exactly 240x135 full row-major pixels, little-endian float64 HDR cast once to resident float32. The second order is manifest indices [0,20,1,21,...,19,39], retaining row-major order. Never reverse reverse-named frames again; never sample, sort, or shuffle pixels.

Four distinct scenarios: manifest_order/cold_per_frame; manifest_order/warm_across_frames; alternate_off_on/cold_per_frame; alternate_off_on/warm_across_frames. Cold means empty decoder slots, not cold CPU cache. Cold resets immediately before every frame. Warm binds to an empty cache at the start of each arm/scenario trial and retains state across the forty frames, never across independent trials. No cache prefill is allowed. The one warmup is a separate complete scenario per arm, after which measured trials start empty again. Raw, baseline, and gather have no persistent state.

Nine trials per scenario, with starting arm rotated by trial number and order reversed on odd trials; each arm and scenario runs sequentially. Identical checksum arithmetic and C loop for all arms. Record every frame loop time, reset time, trial bind time, total loop time, setup-inclusive total, median per-frame and scenario totals, and ratios to raw, gather, and baseline. Bind and reset occur outside separately reported pixel-only timing, but the primary measured batch wall time includes bind/index validation and every reset. Also report the sum of measured setup and pixel-loop intervals. Any gap from Python dispatch and counter reads is identified; no allocation cost is silently excluded (the cache uses fixed caller storage). All timed cache work is real evaluation, not modeled locality. No artificial prewarming outside recorded setup. Cache counters remain enabled in timed code; report their overhead as part of this implementation rather than silently subtracting it.

Capture counters after every frame, outside timing, plus final totals, including available hit/miss/block decode/eviction counts. Counter deltas are per frame, with reset behavior documented. Do not infer hit rates from speed or substitute a locality simulation for actual timing. Full exact correctness and lifecycle gates belong to independent tests; checksums are an additional fatal parity guard, not a replacement.

Record same flags as prior benchmark: cc -std=c11 -O2 -fno-fast-math -ffp-contract=off -fstack-usage -fPIC. Report compiler identity, source/binary/input/plan hashes, process/load snapshots, object text/read-only/writable-static bytes, actual sizeof(cache/context), and per-function .su stack. Separate benchmark-wrapper static context storage from implementation static data. Stack sums are conservative compiler chain estimates excluding libm/ABI costs, not observed high-water.

No heavy benchmark execution until the parent confirms correctness/sanitizer/other CPU-heavy tests idle. Host is not reserved against unrelated load. Results imply only host profile-evaluator timing, never renderer or device throughput. All arms and all observations are retained, including regressions. New bench files only. Shareable allowlist includes source, plans and aggregate metadata/results, never private fixture arrays, profile-data headers, or linked binaries/objects embedding them.
