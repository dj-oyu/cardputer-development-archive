# Independent AA overlay code review

Source invariant audit passes. Only the workspace declaration and compile-time layout assertions change production C. build_core.sh is path-only repointing. Entire orchestration, arithmetic, copy operations, charge/guard budgets, packet/field parsing, and private-build production sources are byte-identical to completed segmented-model baseline.

## Lifetime and C aliasing

Both contiguous-depth and five-band entry points execute all center strips before entering their quarter loops. rrh_finish_row/db_finish_row are the only center-ID readers. Each pending row is completed after the next eight-row strip, with its two predecessor ring rows preserved; the last seven-row strip finishes every row without a pending tail. Target-mask validation reads targets, not IDs. Only then ring_aa_geometry writes winner arrays, initializing all active record/face/depth slots before winner consumption. No old center ID is read as float, nor vice versa. The build is C11, using anonymous struct/union members, with no cross-arm value reinterpretation and no escaping pointers relied on after the phase boundary.

The center arm retains non-overlapping delayed HDR (5760 bytes) and ten-row IDs (4800 bytes), total10560. Quarter arm remains13440. The ID start equals winner-depth start. Pending memcpy still uses sizeof delayed_center_hdr, asserted5760, so cannot overwrite adjacent IDs. Repeated calls enter the center arm again and initialize every row before neighbor use. No declaration of external workspace ownership changes.
