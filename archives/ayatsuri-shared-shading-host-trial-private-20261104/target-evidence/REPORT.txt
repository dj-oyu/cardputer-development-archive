Observations
1. Sharing succeeds at eliminating duplicated normal-dependent work per A/B
   pair. Baseline shade_pair calls shade_sample twice, each containing a
   conditional powf site, one sqrtf site and normalization divide paths.
   Both shared pairs contain one such normal/powf computation and two color
   helper calls. The same mesh normal on opposite sides remains independent.
   Counts are conditional static call sites, not always-executed runtime calls.
2. Context matters. In model, default candidate inlines color calculations:
   mesh_packet has12 lroundf sites, two terms_prepare sites, instead of four
   baseline shade_sample sites. Candidate grows object text by1389 B and
   local mesh frame by48 B. Bounded outlines the color helper (four mesh
   calls to one3-lroundf helper), limiting growth to106 B and restoring the
   local mesh frame to1424 B. Helper frames still nest; equal caller frame
   does not prove equal total peak stack. External math/ABI/window-spill stack
   and whole-firmware linking were not measured.
3. In the small pair TU, GCC already outlines from_terms even with 'inline'.
   Candidate/bounded allocated section bytes AND code/literal relocation
   records match exactly. Their .su frames also match. Whole object/debug
   bytes need not match because header source locations differ.
4. The final store is NOT one S3 32-bit destination store. Baseline pair uses
   s16i to out+0 immediately after colorA and s16i to out+2 after colorB.
   Shared pair uses s16i into colors at SP+16/+18, then a10=destination,
   a11=SP+16, a12=4 and callx8 via memcpy relocation at .text.shade_pair+0x16f.
   The callee/library implementation and destination alignment were not
   linked or executed, so atomicity or one final physical store is not claimed.
   Model mesh has13 memcpy sites versus11 in baseline; the added front/back
   color copies also remain external4-byte memcpy calls. Other original
   4-byte decoder memcpy sites must not be attributed to this optimization.
5. Registers and spills are distinguishable. Xtensa windowed call arguments
   use a10..a15 before callx8 (callee a2..a7), with additional args on stack.
   IPA scalar-replaces the terms pointer: front/back/spec cross in scalar
   argument registers; thin is passed in the outgoing stack argument at SP+0
   and the64-byte helper reads incoming SP+64. These are ABI argument slots.
   Pair's incoming out pointer at SP+80 is also an argument, not a spill.
   colors[0/1] at16/18 is the addressable local memcpy source array.
   Separate reload RTL explicitly marks %sfp scalar save/reloads: baseline
   preserves m atSP+0 between its two calls; candidate preserves thin/back/spec
   atSP+32/+36/+40 over the first color call and reloads for the second.
   Those scalar preservation sites are register-pressure/call-clobber traffic,
   not evidence that every stack access is a spill. IRA tentative 'Spill'
   lines are not dynamic spill counts. selected-evidence.txt quotes examples.

Conclusion and limits
Normal-term reuse is visible on S3, but naive inlining increases code/live
state. A bounded color boundary trades more calls for much smaller model text
and caller stack. This is an observation, not a performance/adoption decision.
The 4-byte external memcpy is an actual target difference from the host result.
No formula approximation, precision change, code fix, cycle/device test,
firmware replacement, public push, CI or PR was performed. Numerical runtime
identity on S3, link relaxation, actual cycles and total peak stack remain open.
