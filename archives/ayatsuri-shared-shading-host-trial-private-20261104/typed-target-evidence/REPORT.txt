Calls and actual final stores
- mesh_packet has13->11 external memcpy static sites: the two added color-copy
  sites disappear; existing decoder/other memcpy sites remain. Four color
  helper and two terms_prepare sites remain, with unchanged shader arithmetic.
- shade_pair has1->0 memcpy sites. The first result stays in a7 across the
  second color helper. Only AFTER that call, destination is loaded from the
  incoming pointer argument at SP+80, then:
    .text.shade_pair+0x15e: s16i a7,a8,0
    .text.shade_pair+0x161: s16i a10,a8,2
- MODEL front fields are inside a known-aligned vertex struct. GCC combines
  the two type-correct assignments into register packing and ONE s32i to the
  actual vertex at+12 (.text.mesh_packet+0x10d8), after the second helper.
- MODEL back uint16_t* has only its existing type alignment. It uses TWO s16i
  (.text.mesh_packet+0x132e B at+2, +0x1331 A at+0), after both computations.
  The compiler can schedule the two nonvolatile stores in reverse order; no
  pair atomicity or externally observed store-order guarantee is claimed.
- The PAIR is likewise only a uint16_t* output and keeps two halfword stores.
  There is no forced/assumed unaligned32-bit store.

Registers and memory traffic
The typed pair's addressable colors local is eliminated; reload RTL has no
colors[0]/colors[1] local-memory references. ColorA is kept in a7. In the model
front it stays in a7 and is packed with colorB; on back it stays in a6.
Pair's shared front/back scalars cross calls in preserved caller registers
(a4/a2). Control reload RTL preserves thin/back/spec at SP+32/+36/+40 over the
first helper; typed reload instead preserves thin/spec at SP+16/+20. These
%sfp scalar preserve/reload sites are distinct from explicit local arrays.
The outgoing thin argument at SP+0 is ABI traffic (the scalarized helper has
seven arguments). Incoming pair output pointer at SP+80 is also ABI traffic,
not a spill. Helper frames remain64/80 and the pair frame stays80 despite the
removed copy/temp accesses. Model normal/projection/index arrays and unrelated
scalar spills remain; no raw stack-access count is presented as a spill count.
selected-evidence.txt gives assembly and reload excerpts, with full dumps saved.

Limits
This is object-code observation, not adoption or runtime acceptance. No S3
numerical execution, cycles, FPS, total peak stack, register-window overflow,
link-relaxation effects or hardware behavior was measured. Host correctness
work is independent and not claimed here. Original checkout/settings, SDK,
software installs, public repository, CI and hardware were untouched.

Reproduce
