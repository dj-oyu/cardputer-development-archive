# End-to-end fixed-point investigation

Private research checkpoint, 2026-11-05 (completed bounded stage). No device operation or publication. This report links independently tested prototypes; it is not a production all-integer renderer or a speed claim.

## Current result

Keeping values integer across adjacent stages is feasible under explicit range and error contracts. Integer data alone does not make every operation an ESP32-S3 PIE eight-lane operation. The current source geometry uses signed32 coordinates; projection/edges need signed64; distances require sqrt/division; watertight visibility/nearest-order semantics still need a separate contract. The most natural signed16 SIMD work is bounded interpolation and normal/direction dot products.

## Q16 versus Q20 cost

In this signed32 format, storage, loads and adds use the same widths; multiplies that fit the same signed64 intermediates can use the same instruction shape with different shifts. Q20 values are16 times larger: products256 times and triple products4096 times, reducing overflow headroom. New multiword arithmetic, range scaling or narrower admitted domain can change cost. Neither position representation is automatically signed16 PIE input. There is no Q16-versus-Q20 target timing measurement.

## Mixed-precision decision

There is not yet evidence that permanent facial/edge precision tags are needed. SourceQ16/screenQ10 yields fewer changed coverage decisions than sourceQ20/screenQ8 in this test, so input and screen precision must be separated. A shared higher-precision source plus range-proved local arithmetic is a cleaner first comparison than mixed source labels, which save no bytes here.

Discarded Q16 source bits cannot be recovered later. Adjacent triangles/partition duplicates must share a consistent projected coordinate grid. Independently changing face grids risks cracks/double ownership. Silhouettes move with camera/deformation; thin triangles and near-edge sample margins are more direct numerical conditions than semantic face tags. Adaptive fallback adds branch/preparation costs and must be tested across motion. No heuristic is accepted without final-image/shadow evidence and a declared error policy.
