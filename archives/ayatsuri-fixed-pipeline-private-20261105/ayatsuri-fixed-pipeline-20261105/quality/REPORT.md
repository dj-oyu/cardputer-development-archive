# Private numerical audit and validation plan

## Decision

Start integer-first at the conversion/attribute boundary, not by replacing geometric predicates. Keep the current F32 pose/screen/depth and F64 world/interpolation/visibility/lighting geometry behavior as the reference. A new linear material representation and explicitly scaled HDR accumulation can be independent experiments. Preserve current SNORM16 values and their /32767 decoding; they already are integer data. Do not reinterpret them as Q15.

This work only read the permitted current inputs and existing source; it made no renderer changes, renders, public writes, or device actions. `measure.py` and `measurements.json` are private diagnostics. Quantize/dequantize errors are representation experiments, not image-quality equivalence evidence. Counts below include repeated scenarios where stated.

The script records exact snapshot filenames and SHA256 hashes. All 40 HDR observer reports say complete and each HDR file contains 32,400 RGB pixels.

- AY model: 1,163 vertices / 3,489 local XYZ components; 54 mesh records, 1,564 triangles, 55 nodes. Native XYZ range −138.68017578125 to 45.18385696411133. Masks are exactly −1. Normals lie in [−1,1]. The difference in source/compiled vertex counts is not interpreted as geometry loss; packaging can repeat vertices.
- Snapshots: 40 × 1,163 = 46,520 vertex occurrences; 62,560 triangle occurrences; all 2,160 records are lossless mode5 normal-pair records. Native world XYZ range matches compiled XYZ for these saved cases. Screen XY 15.458786 to 155.844635; F32 depth −76.925148 to 54.626884.

- Prepared lights: 120 light instances across 40 headers. Center components −4 to 6.76618481, radius 1.5 to 2, power × RGB / π² 19.2636893 to 86.1230061. World-radiance channels 0.241499995 to 0.699999988. These are descriptor ranges, not observed per-ray kernel maxima.

## Quantization experiment

All tests use floor(x × scale + 0.5), matching the current asymmetric normal rounding convention. Overflow is counted before any clipping; reported errors are mathematical quantization errors, not errors after representable-value clamping. Values with overflow must be rejected or use a wider fallback, never silently clamped.

- Native local signed int32 / 2^16: 2,644/3,489 components changed, max error 7.6293945e−6 native units, RMS 4.7307191e−6, no overflow.
- Native local signed int32 / 2^20: 294/3,489 changed, max 4.7683716e−7 native units, RMS 1.1398524e−7, no overflow. Dividing native error by 38 gives at most 1.254835e−8 source-world units for the coordinate conversion alone, before general transforms/interpolation.
- Native local signed int32 / 2^24: 11 components overflow [−128,128); unusable for this current model without rebasing/widening. Across repeated snapshots the same issue occurs 440 times.
- GLB storage signed int32 / 2^20: 2,694/2,982 changed, max 4.7683716e−7 storage units. /2^24: 637 changed, max 2.9802322e−8, no current-input overflow. This illustrates why source-unit and native-unit precision must not be conflated.
- Screen signed int32 / 2^20 reproduces all 93,040 measured components exactly, but has only [−2048,2048) range and fails the existing allowed ±4096 contract. /2^16 changes 32,160 components, max 7.6293945e−6 pixels. Neither observation proves raster coverage preservation for arbitrary geometry.
- Replacing decoded SNORM16 with signed int16 / 2^15 changes 266,640/279,120 components; 1,440 +1 endpoints overflow. Keep /32767 semantics instead.
- Source linear material UNORM16 /65535: 26/27 changed, max 6.8832492e−6. Approximate current decoded palette UNORM16: 47/48 changed, max 7.5624752e−6.
- Final HDR uint32 /2^20: every channel changed; max 4.7683697e−7, RMS 2.7507279e−7, no observed overflow. uint32 /2^24 max error 2.9802252e−8 and range [0,256), but no universal proof that 256 is sufficient. /2^16 max error 7.6293789e−6. None of these tests recomputed shading, visibility, AA, tone mapping, or RGB565 output.

## Formats and error budgets to test

Use explicit `(storage bits, signedness, fractional bits / divisor)` instead of ambiguous Q names.

1. Source-local XYZ: keep original F32 reference. Candidate int32 with 20 fractional bits in source units (range ±2048) or object-relative int16 with a per-object power-of-two exponent and origin. Export a range/error certificate covering each object's full allowed poses and hierarchy. The current file alone cannot establish future pose bounds. Object-relative int16 is a storage option only until geometry tests pass. If quantization uncertainty cannot satisfy a certified bound, use F32/F64 fallback. Do not quantize separately at each hierarchy level.
2. Transformed native-world XYZ: preserve current F64 arithmetic initially. Native int32 with 16 fractional bits accommodates the existing ±4096 local range but loses low bits; int32 with 20 fractional bits fits this model but not the full contract. Conservative transformed bound is |δp_world| ≤ |A| |δp_local| + |δA| |p_local| + |δt| componentwise, with extra terms for quantized matrix products. Normal inverse-transpose is ill-conditioned near singular scales. Instrument hierarchy norms, determinant/conditioning, and dynamic extremes before selecting fixed geometry.
3. Screen/coverage/depth: preserve F32 fields and current double edge/interpolation comparisons. Existing screen limits permit ±4096; int32/2^16 is a range-safe candidate, not a coverage-safe one. Edge products need int64 or wider with a proven full-coordinate/subpixel bound; mixed fixed fractional products can exceed int64 (e.g. high fractional count squared). Shared edge/top-left, degeneracy, side and depth tie decisions require exact comparison against the reference, not a color PSNR waiver.
4. Normals: preserve current SNORM16 integer codes, mode4 vs mode5 eligibility, asymmetric front/back rounding, F64 interpolation and normalization. Do not halve normal precision solely because direct cosine error is small: normals drive bounce frames, ray directions, and branch thresholds. Near-zero interpolated normals magnify perturbations without a useful universal angular bound. Keep geometric normals and ray directions double initially.
5. Linear albedo: candidate UNORM16 /65535, or uint32 /2^20 to reduce error if integer ALU permits. Preserve RGB565 source codes in compatibility mode. A new Blender-linear albedo path avoids the present encode-to-RGB565 then decode loss, but is an intentional appearance change, requiring separate Blender-reference and legacy-compatibility tests. Do not label it bit-equivalent. Nonnegative barycentric interpolation bounds albedo error by max vertex error only when weights themselves remain unchanged.
6. Cosines/lighting weights: nonnegative bounded cosine can use UNORM16; signed dot intermediates need signed storage and wider sums. Keep disk sample positions, distance, reciprocal/normalization, positive-kernel test, and visibility decisions double in v1. The kernel cos_source cos_receiver / distance² is NOT bounded by 1; the current 1e−9 endpoint exclusion permits enormous theoretical values. No actual per-ray weight trace was available/produced. Select fixed kernel range only after measuring intermediate maxima and proving a minimum separation, with explicit overflow failure/fallback.
7. HDR: candidate uint32 with 20 fractional bits, range [0,4096), and uint64 accumulators for nonnegative sums/products, but only after range proofs for each operation. Do not infer accumulator safety from the 5.87 final-image maximum. Signed wider intermediates may be needed in tone mapping. Round once after a block of products rather than per sample if reference semantics and overflow proofs allow it. N separately rounded contributions can accumulate N/(2S) absolute quantization error before material gains; total error also includes gain/kernel error. A starting acceptance budget for the isolated color-only experiment is max absolute HDR error 1e−4, plus relative 1e−4 above HDR 1e−3 and explicit near-black reporting. These are proposed engineering gates, not demonstrated outcomes or user-approved visual tolerance.
8. Tone map/output: keep current AgX and output quantization reference first. A tiny HDR error can cross a tone-map/LUT/RGB565 boundary. Approximate HDR arithmetic cannot promise unchanged output pixels. If output identity is a requirement, demand zero RGB565 differences or implement a certified boundary fallback.

## Comprehensive rendering gates

A. Freeze exact source hashes, compiler/build flags, float contraction/FMA policy, architecture, camera/light/material/pose generation and traversal order. Separate batching-only, attribute storage, material representation, and fixed arithmetic variants; never change them all in one candidate.

B. Converter round-trip unit tests: versioned format, endian/alignment, scalar extrema, signed zero, ±1 normals, asymmetric ties, color 0/1 endpoints, invalid NaN/Inf, overflow refusal, negative/nonuniform/near-singular scale, parent chains, transforms and axis/38 conversion. Verify topology/index order, sidedness/material IDs/masks and lossless normal-pair fallback. Add exact content range certificates and animation/pose envelope tests. Compare Blender source values as well as compiled native values.

C. Geometry gate: for every original center and quarter AA sample compare coverage, owning primitive, edge open/closed behavior, face side, depth bits/tie ordering, world position, normal and barycentrics. Test touching/coplanar/overlapping triangles, degenerate or nearly zero-area faces, shared edges, offscreen limits, negative coordinates and triangles spanning entire screen. Preserve original epsilon semantics; VIS_SEGMENT_EPSILON=1e−5 and disk endpoint epsilon=1e−9 are different conditions, neither is a general allowable coordinate-error budget.

D. Visibility/transport gate: compare each shadow boolean, segment endpoint exclusion, nearest triangle identity/tie rule and hit distance; include grazing and nearly parallel rays, self intersections, thin gaps, lights near receiver/disk plane, forward/reverse submission, flipped winding, front/back double-sided material, normal interpolation cancellation, bounce frame axis-choice boundaries and all allowed 16/64 quadratures. Compare scene generations, cache fingerprints, failure codes, budgets and counters. A normal-code change can alter secondary hits despite tiny angular error.

E. Actual scene gate: re-render all existing 40 on/off cases (2 views × 5 parameter cases × order × arm) plus existing production baseline cases. Save pre-tone-map HDR, final RGB565, target/owner/depth masks, floor/world categories, and provenance. Add posed/animated and scale-stress cases because saved scenes have matching local/world coordinate ranges and do not prove general transformed bounds. Keep actual images private.

F. Color gate: report max/mean/RMS and absolute/relative HDR errors, dark-pixel errors, quantiles, changed RGB565 pixel/channel counts and max channel steps, masked character/floor/background and boundary results, PSNR/SSIM plus visual crops where appropriate. No aggregate metric may hide topology/visibility differences. First establish batching-only bit identity; then isolate each approximate stage. HDR observer captures final pixel RGB only; instrument per-contribution/cosine/inverse-distance/kernel/intermediate accumulator extrema separately in a future authorized implementation.

G. Integer execution gate: scalar vs every supported vector width and tail count; deterministic per-pixel summation/sample order; no inter-lane data dependence; masked invalid lanes do not issue rays or consume budgets; no compiler-dependent signed overflow/right shifts; explicit widening before multiplication, rounding and saturation/failure contracts; sanitizers, adversarial max values and repeated-frame/cache invalidation tests. Benchmark on target ISA because integer-first does not imply faster vector instructions or cheaper reciprocal/normalization.

H. Deployment gate: all existing API/lifetime/storage/failure-atomicity/budget checks remain; measured additional scratch/stack/flash fit caps; speed measured end-to-end including unpack, conversion, fallback and tails, not just multiplies. Reject candidates failing correctness regardless of speed. No quality claim before re-render tests; no speed claim from this audit.

## Coordination note: converter sidecar contract

The converter worker's proposed AYFQ source is `compile.json` pre-×38 `parts.positions` in native-basis metres, NOT this audit's legacy AYNM XYZ or raw glTF accessor basis. Its reported current range approximately −3.65..1.19 m is consistent with native AYNM /38. Do not mix that range with the raw glTF stored XYZ range above; basis conversion changes the signed axes. For pre-×38 metres, frac16 has half-step 7.6293945e−6 m and frac20 4.7683716e−7 m. Quantizing legacy native XYZ then /38 has 38× finer physical spacing than quantizing metres at the same fractional count, so the native-component changed counts cannot validate this new sidecar. The converter worker owns measurement of the exact sidecar source values.

For proposed linear RGB integer 0..32767 decoded /32767 (UNORM15, not signed Q15), ties-to-even on the 27 source-material components changes 26, max absolute error 1.45276748e−5, RMS 8.67825761e−6. The representational half-step bound is 1/(2×32767)=1.52592547e−5. This representation reaches 1 exactly and must not use /32768. This tests source materials only, not eventual per-part material generation/interpolation/render.

Proposed symmetric ties-even normal conversion is a NEW contract relative to existing floor(x×32767+0.5), with front/back independently rounded before mode5 eligibility. Exact ±half-integer scaled inputs can change one code, and legacy front/back pairs need not be exact negatives there. Either preserve the old rule in compatibility mode or explicitly test/document the new symmetric rule as an appearance/visibility-affecting change. No measured changed-count between the proposed full converter and old normal evaluator is claimed here. The Q15 requantization experiment above tests a different divisor and is not that comparison.
