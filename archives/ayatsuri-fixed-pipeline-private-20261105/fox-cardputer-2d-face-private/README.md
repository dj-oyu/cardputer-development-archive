# 眉と口を顔面2D描画にする試作

## 推奨

眉毛と細い口線は、目のように **顔の表面に追従する2D表現** にするのが、この小型画面では合理的。鼻・白い口元・頬・顔の輪郭は3Dのまま残す。単純に画面上へ重ねるHUDとは区別する。

最新軽量モデルは眉58三角、口線36三角、鼻下線6三角。計100三角を除いた試作はモデル1,882三角、床込み1,884三角になる。削減は約5.05%にとどまるので、主な利点は「細い線の低ポリ化による潜り込み・欠けを避けること」と表情調整の容易さ。速度の改善は未計測で、2D化すれば必ず軽くなるとは断定しない。

## 今回の画像

- 左/上: 最新2kモデルの3D線。
- 右/下: 同じモデルの顔材質に2Dマスクで色を混ぜた試作。
- 原本 `fox-bubble-bold.blend` の眉・口線を頭の座標系の XZ に投影し、128×64の各1chマスクを作った。最新原本や既存2k成果は変更していない。
- 不透明な顔の既存 Base Color へ混ぜるので、新しい透明ポリゴン、透過ソート、デカール同士の深度競合を追加しない。顔・鼻・目による通常の遮蔽は残る。
- 頭に親子付けした投影座標を使い、カメラではなく顔に固定。正面・斜め・横寄りの視点を比較した。
- 口元の3D meshとSmile shape key変形は残る。線だけの置換でSmile全体を2D化したわけではない。
- 4つの選んだ表情マスクを比較した **見た目の試作**。全ての連続的なBrow Raise/Furrow/左右眉/Smileの組合せをruntimeで実装したものではない。保存blendはneutralのマスクを表示する。
- 投影した口線の一部は、以前3D口元の中に隠れていた部分も見えるため、口角のカーブが変わる。現時点で元画像への完全一致や最終デザイン承認は主張しない。
- 画像はBlenderの比較であり、Cardputer実機出力ではない。

## 方法の比較

1. **顔材質で2Dマスク/線を描く（推奨）**
   追加meshなし。顔のdepthと遮蔽をそのまま使う。視点に応じて顔に沿って短く見える。左右眉・口角を顔座標で動かす設計にできる。眼球材質と同じく局所座標・制御値を利用する考え方で一貫する。ただし現runtimeの定数色AYFQにはこの機能がなく、2Dの評価方式を新たに実装する必要がある。

2. **薄い貼り付けmesh/quad**
   材質を顔と分けやすいが、表面へ密着する追従・少量の深度差・alpha test・影の扱いが必要。低ポリ顔に重ねると今回と同様の潜り込みや浮きが再発し得る。単一の平面では斜めから浮いて見える。

3. **画面上に重ねるsprite**
   正面固定なら簡単。頭の回転、鼻・目による遮蔽、横顔の縮みを別実装しないとシールが画面に貼り付いて見える。今回の3Dキャラクターには第一候補にしない。

## メモリ・処理

128×64 R8の眉/口マスク2枚は16KiB/表情。4表情を素直に持つと64KiB。64×32なら4KiB/表情になるが、近接での線幅とアンチエイリアスを再評価する必要がある。これは想定したCPU用R8形式の理論値であり、Blenderのtextureメモリ量ではない。

細い線だけなので、画像全体を保存せず「xごとの上端/下端」や少数の曲線パラメータで表す候補もある。今回の8マスクは各列に分離領域がなく、128列×上下2byte×8枚＝2,048byteで **alpha>=128の二値輪郭だけ** は厳密に復元できた。ただしアンチエイリアスと任意の中間表情の再現は未検証。この2KiB表を実際の比較レンダーに使ったわけではなく、圧縮可能性を調べたもの。

いずれも評価を眉/口の小さい範囲に絞り、制御値はframe毎に準備するのがよい。連続表情にするなら、原本のRaise/Furrow/Worried/SternとSmileの変位・左右制御をテーブル/曲線へ移す。最終的には全描画器・メモリ・実機速度で検証が必要。
