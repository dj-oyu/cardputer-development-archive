# Private snapshot retirement proof

## Scope and verified results

`lease.c/.h` is asset-independent, allocation-free, task-context ownership bookkeeping. `render_adapter.c/.h` is PRIVATE integration with the real frozen character scene prepare/preflight/composite code, not generic product code. Existing repositories and the parallel QuickJS two-core work are unchanged.

Host O2 and ASan/UBSan tests exercise delayed and out-of-order retirement, duplicate/stale completion, saturation, close while building/reading, failed updates via abort, no-wrap generation/ticket exhaustion, 60,000 pthread pin attempts and 10,000 actual producer/consumer generations. Renderer integration exercises all 34 bands, two retained strip slots, reverse completion, inline/reentrant completion and failure after earlier submissions, snapshot cancellation mid-render and transactional invalid-control update; immutable pixels are checked immediately before retirement. No hardware DMA is simulated as hardware proof. Generic C compiled warning-clean using the available Xtensa compiler. Parent coordinates QEMU/full firmware work separately.

Run `cc -std=c11 -Wall -Wextra -Werror -O2 -pthread lease.c test.c -o test && ./test` here, and `python build.py [san]`. Existing source dependencies are read from their original private paths. Sanitizer proof is memory/undefined behavior, not a race-detector proof. Initial renderer LeakSanitizer failed because this environment runs under ptrace; ASan/UBSan passed with leak detection disabled (see render-san-noleak.log). No leak-check pass is claimed.

## Production source audit (qemu-render-20261111, 828baa3af69c55e7884c53557ea39f91190010a0)

- `main/ayatsuri/ayatsuri_model.h:69-86`: current mesh patch/depth and sided arrays are borrowed, NOT owned packets. Copy all pointed-to storage before targets/evaluate/dispose; copying just descriptors is insufficient.
- `main/ayatsuri/ayatsuri_model_skin.h:14-28`: geometry descriptors and vertices are synchronous immutable borrows, disjoint from instance/arena. Evaluation replaces instance packets. Copy into frame-owned snapshots before any mutation/disposal. The skin API deliberately does not own submission, commit, retry or presentation.
- `main/hal/board.c:180-265`: SPI reaping requires the exact queued descriptor; timeout/unexpected descriptor retains ownership. A status error alone is not proof that DMA readers have stopped.
- `main/hal/board.c:720-840`: async present may copy to driver storage, use a borrowed strip, or use a ring depending on build/mode. Present return is not universally retirement. Descriptor/payload must remain unchanged until exact reap or documented hardware abort/drain.
- `main/hal/board.h:109-111`: `board_present_frame_end` only invalidates window reuse; it neither drains nor acknowledges transfers.
- `main/hal/board.c:1019-1040`: finish retries timeout. Other errors need branch-specific interpretation; do not release all leases merely because finish returned nonzero.
- `main/ui/kasane/ksn_render.c:2417-2439`: complete rendering calls finish after earlier submission even if a later provider fails; finish failure cannot acknowledge the frame. A null finish function is not sufficient for an asynchronously borrowing display.
- `main/hal/lcd_spi.c:77-119`: existing ring uses portMUX and ISR critical sections, with separate DMA EOF and SPI completion. Volatile fields alone are not its concurrency mechanism.
- IDF `components/freertos/FreeRTOS-Kernel/portable/xtensa/include/freertos/portmacro.h:170-222` explicitly defines SMP critical sections using spinlocks. `include/freertos/semphr.h` documents static mutexes and prohibits mutex use from ISR. Optional `lease_freertos.h` uses static task mutexes; host tests use pthread mutexes. No 64-bit lock-free assumption: all ticket/generation access is under the lock.

## Caller contract and integration boundary

1. Allocate/init pool, fixed slots/readers and lock before publication. Slot payloads are exclusive disjoint caller storage, correctly aligned for their use. No allocations occur in the pool. Provisioning failure must return before pool publication. A pool cannot be copied/moved/reinitialized while callbacks might still reference it.
2. Producer acquires a WRITING lease, fills every needed control/geometry/packet field, validates, then publishes. Publication transfers to immutable ownership; producer never writes afterward. Build failure aborts only its WRITING lease, leaving older published snapshots unchanged. Close during build does not free under the writer: publish fails and producer must abort after it stops writing.
3. Every asynchronous reader pins before dispatch, retaining the exact unique ticket (including pool identity, slot, generation and serial). Reads require that pin for the complete access interval. Retire denies NEW readers but leaves existing readers alive. Owner must arrange pin-before-retire when replacing latest state; never read raw pointers before pinning.
4. Complete only after reader stops, not on request to cancel and not on submit success. Callback can complete inline; callbacks run outside the pool lock. Duplicate/stale tickets cannot release a later reader or a newer generation. Counter exhaustion rejects work instead of wrapping. Ticket capacity and slot exhaustion return false immediately; adapter makes at most one pump/retry, then returns backpressure/failure.
5. CPU render holds one snapshot pin through prepare/preflight/all bands. Caller exclusively owns render_scratch during the call. Each output strip has its own pin before submit; scratch and snapshot may retire after CPU work because transport retains only pixel strip storage, not their addresses. An async renderer that retains scratch must separately lease it. Never reuse static scratch for simultaneous renderers.
6. Submit owns the passed ticket regardless of its boolean result and must eventually retire it only after access stops. If backend rejected without retaining anything, it completes inline before returning false. If submission outcome is uncertain, retain the lease until an exact completion/drain proves safety. Cancellation cannot forge completion.
7. Close rejects new work and retires published slots, without freeing active readers/writers. `lease_drained` proves no active lease, NOT absence of future duplicate callbacks. Destroy/free pool, mutex and storage only after all writers stop, all leases drain AND callback source is unregistered/joined. If a backend loses completion, safe behavior is retained storage/backpressure, not reuse. No disposal timeout can override that.
8. ISR must not call task-mutex APIs. Use reliable FreeRTOS notification/queue bookkeeping and reap in owner task; queue overflow must preserve a retriable pending record, never silently drop the only retirement evidence. The existing board driver does not expose this pool's tickets: actual target integration must associate exact pending descriptor/strip with ticket, and route successful reap or proven abort to complete. This adapter does NOT falsely claim that wiring is implemented.

## Memory

Host pool/slot/reader sizes: 72/24/40 B. The Xtensa compiler measured 40/24/40 B; two pools with two slots/four tickets each cost 496 B, plus target mutex storage. Two 15,976 B snapshots replace the old two snapshots. Two 1,928 B strips add 3,856 B staging until board lending is integrated (not an automatic replacement for its 3,840 B buffer). Private renderer scratch is 86,848 B on this host; target accounting is recorded in the firmware budget report. This is lifetime correctness work, not proof that full production firmware fits internal RAM.

## Follow-up: completed dual-core QEMU validation

The bounded socket-free ESP32-S3 run in `qemu/run/uart.log` completed successfully with production IDF v6.0.1 FreeRTOS mutexes and this exact generic lease implementation. Configured cores=2; observed producer core0 and consumer core1 (pinned task). It passed 2,000 cross-core producer/consumer handoffs and the generic adversarial checks, then real private prepare/preflight/composite rendering with delayed/reverse/inline strip retirement, submit failure, snapshot cancellation, invalid-update abort. Frame hash `c526e444` matches host O2/ASan. `qemu/run/run-metadata.json` records command, timeout, hashes and completion. The reused runner's profile/marker naming is historical; this is the lease guest, not the long eye sweep. No AF_UNIX, display, network, physical hardware or production worktree was used. This proves guest task synchronization, not actual ESP32 cache coherency/DMA interrupt timing.

`lease_spi.c/.h` is an isolated, target-compiled IDF adapter, NOT installed in board.c. Audit correction: frozen production board uses SPI-master directly, not esp_lcd. It has only an optional diagnostic `post_cb` (`board.c:158-174,568-575`). The adapter uses exact `spi_transaction_t*` returned by `spi_device_get_trans_result`; it never relies on FIFO identities or calls the pool from ISR.

SDK source `components/esp_driver_spi/src/gpspi/spi_master.c:1218-1267` queues before `spi_bus_lock_bg_request`; unknown submit errors cannot universally be treated as unborrowed. Adapter marks record active and pins before queue, retaining every nonzero submission outcome. A prequeue failure may therefore remain conservatively pinned forever; no false recovery is claimed. The owner must stop and preserve storage until an independently proven quiescent teardown; this adapter intentionally exposes no unsafe force-release.

SDK source `spi_master.c:1270-1291` dequeues completion, uninstalls DMA temporary buffers, assigns returned descriptor, THEN may return INVALID_STATE for DMA failure flags. An exact returned descriptor therefore retires storage even with that specific nonzero status; no descriptor means no retirement. API docs `include/driver/spi_master.h:230-248` prohibit descriptor modification until its return. Unknown descriptors preserve all leases.

QEMU linked mock queue/reap functions to exercise the REAL adapter's bookkeeping: two slots, error after submission, unknown completion, reverse-order exact descriptor completion and nonzero-but-retired status. UART labels this `LEASE_SPI_MOCK_EXACT_DESCRIPTOR_PASS_NOT_DMA`. It does not validate hardware SPI/DMA or actual SDK interrupt delivery. Actual SDK headers compile and the audit establishes the intended integration edge; production wiring and hardware verification remain outstanding.

Target static mutex storage is88 B each (target compiler evidence), adding176 B for two pools to496 B bookkeeping. Neither source driver descriptors nor private strip staging replaces board memory automatically.
