## Oracle implementation repair before selection
The initial sequential float32 BVH parity stepping failed the source→source identity control and is INVALID, retained under invalid-parity-diagnostic. It cannot diagnose candidate failures. Replace sign oracle with float64 generalized winding (solid angle sum /4π), classify only within triangleCount*float64epsilon*256 of zero or absolute one; otherwise unresolved. Robust geometric margin remains unchanged. Re-run all candidates and source identity. This numerical tolerance is an accumulated floating-operation bound, not a geometric fit threshold. Independent double ray and closed-box fixtures will validate sign classification. No candidate was selected using invalid results.
The initial float64 winding implementation passed source identity and all 2400 independent double-ray checks but returned unresolved on two analytic box points only 2δ from a planar triangulation edge. Its accumulated-operation error bound did not cover this conditioning. Rather than loosen the tolerance, the final implementation evaluates winding intermediates in numpy.longdouble (extended precision), keeps the same float64 error bound, and re-runs fixtures and every audit. Previous float64 audit summaries are retained in winding64-diagnostic. Geometry/δ/view gates unchanged.

No BVH distance is used for containment or correspondences. BVH remains only for pair-view ray intersections; these are finite float32 audits with robust δ exclusion, not exact predicates.
