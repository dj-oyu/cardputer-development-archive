# Next renderer design: separate interior transport and camera-background contracts

Read-only planning from frozen v32, v35 and earlier private evidence. No new render, feature, model edit, threshold change or adopted default. The current 1564-triangle lid8 model and formal v3 remain fixed; the separately authored new model is not substituted. Further BH offset tuning, exposure fitting and high-density loops are excluded.

## Two different remaining problems

The attribution work is in ../fox-v3-aa-response-attribution. Its final independent-review status is reported there, not inferred here. Direction is the main diagnostic below; all response conditions must remain in the eventual acceptance table.

Oblique v32 active reference becoming inactive falls from 991 to 883. ON contains 249 center-missing pixels, 218 covered object-boundary pixels and 416 covered interior pixels. Opaque-mask interior alone still contains 382. Thus fixing sample locations or camera-background pixels cannot by itself resolve the interior response loss. Native center material groups contain orange417/ivory114/cocoa77 inactive responses; Anatomy241 and Tail body165 dominate object counts. These labels describe current center receivers, not proven same source surfaces or unique causal materials.

Inactive FP rises85→98. The increase13 decomposes into center-missing+12, covered boundary+1 and interior0. Original color PNGs are opaque; the partial-alpha foreground mask was made separately with the floor hidden and film transparent. Original RGB therefore contains the authored floor/background mixed by BH, whereas native nohit samples are black. This is a scene/background content mismatch, NOT a straight/premultiplied-alpha inversion problem. Never divide original RGB by the mask alpha.

On the 382 opaque-interior inactive pixels, existing raw response is exactly zero at71, direct response is zero at183, both-frame all-channel >1 occurs at16, and final565 is identical at286. These categories overlap. They do not prove floor-reflection causality, and 286 identical565 values are not proof that greater color precision would restore correct source responses. Clamping, small transport changes and final quantization must not be collapsed into one cause.

## Proposal 1: first-floor-hit reflected direct light, one bounded path

Priority: the next substantial transport hypothesis, not an established fix. The current code explicitly returns after floor Le and omits the floor's reflected light. A first hemisphere hit on the floor would retain its existing Le and add a separately reported Lambert surrogate reflection of the same three DISK lights, with source linear floor BaseColor and the same16 disk samples/visibility. The existing character outer16 sampling remains unchanged. Per receiver contribution is rhoX * mean(Lfloor_reflected); the disk evaluator already contains floor rho/pi, so do not multiply floor rho or pi again. Add no secondary-floor emission, floor world reflection, specular, higher bounces, extra sampling or display change in this arm. The original Principled floor remains untouched in the reference; this is only one explicitly approximate reflected path, not full original floor BRDF equivalence.

OFF and zero floor-rho must reproduce the old result bytes. The floor material/radiance descriptor is copied and generation-bound; changing source rho invalidates it. The albedo scenario also multiplies the source floor BaseColor by0.6, so its descriptor/material generation must change. Fix the two-sided floor receiving-normal rule and ray start/end epsilon before implementation; do not blindly substitute a view-facing normal. Existing floor Le is added exactly once. Test a black floor, zero lights, analytic parallel/tilted surfaces, opaque blockers, conservation/units, source input poisoning, failure-atomic output and old snapshot lifetime before fixed all10 forward/reverse runs. Keep direct, existing world, existing bounce, floor Le and the new reflected component separately observable without sourcing any values from reference images.

Cost envelope from existing actual counters: 70,342/71,667 first-floor hits per front/oblique frame, at most3,376,416/3,440,016 extra disk segments. Transport ray totals would be bounded below the existing20M ray cap (maximum8,061,340), but node/triangle work is unmeasured and is NOT certified under800M/300M. The current stage ledger has only49,142 front reservation headroom: new shader work cannot silently be called free or the old ledger-equivalent. A separate explicit operation reservation/preflight contract and actual admission must precede rendering; no cap increase. Failure means an unscored arm. Source-floor rho requires a small owned descriptor rather than new geometry; exact struct/stack/scene bytes and two-generation peak remain implementation-time measurements. Existing host cost is already seconds, so neither speed nor device fit is implied.

Evidence limit: Lambert/native-rho current proxy still reaches71.31% oblique bright IoU while native is39.24% before AA, making specular addition alone an unconvincing next step. However its retained floor/world/GI and filtered receivers prevent assigning that gap specifically to floor reflection. The floor-emission experiment establishes Le, not reflected-light benefit. A negative all10 result rejects this proposal rather than fitting gain or adding further paths until it looks good.

## Proposal 2: source camera-background resolution, separate from transport

Secondary priority: a clearer representation mismatch, with a narrower likely effect. Introduce an opt-in camera-ray result distinguishing character hit, floor hit and environment miss. Keep current character geometry/winner/lighting unchanged. At no-character samples, intersect the actual authored floor and shade it from source scene parameters. Freeze the exact floor BSDF surrogate, direct/world terms, emission, shadow and normal conventions before running; do not call an incomplete approximation the original full floor BRDF. A true scene miss uses source world radiance. At the floor, use no reference image values; resolve sample HDR against that physical background before the existing sRGB565 step. Do not use reference pixels, foreground-mask values or a handpicked flat backdrop. Do not move the floor, fill geometry holes, drop missing original foreground, or change formal depth/shape masks to label background as character.

This was deliberately excluded from the earlier floor-Le stage. It therefore needs a separately approved experimental scope and ledger, not a silent continuation of that implementation. Initially retain identical4 positions/mask and renderer controls; do not simultaneously enlarge the mask or change filter/profile. Add sphere/plane silhouette and missing-character fixtures demonstrating that coverage is distinct from background shading. Report full FG, opaque interior, partial mask, center-missing, support outside original FG and unchanged character geometry errors separately. A floor-filled missing face pixel is still a character-geometry failure.

The number of additional camera queries is bounded by existing raster samples, but source shading on them is not free. Store no full original-image oracle: a ray-hit tag plus bounded band HDR scratch can reuse the current resolution machinery only after an alias/lifetime audit. All camera/background light and shadow calls must consume cumulative quotas; actual scratch, stage reservation and CPU need measurement. No fit is promised from current counts. FP concentration on added support motivates testing this contract but does not prove the FP will disappear.

## Decisions and stop conditions

Do not combine the two proposals in the first test. Proposal1 addresses a missing light path and could influence opaque interior; Proposal2 addresses background mixture and cannot recover interior normals or absent character geometry. Quality comparisons remain against unchanged v32. If approved, use the verified affine-rho A2 as the implementation base because its RGB/depth are v32-exact; retain A2's distinct final-hit preflight/finite-check/error and reservation contract rather than reporting its resource accounting as v32. Each must compare to unchanged v32, with all10 conditions, original unknown masks, stable inactive FP, FN, reverse signs, full-FG color, response amplitudes, missing/extra shape and all resource counters. A local improvement with broad regressions is not60% acceptance. Neither is implemented or adopted by this plan. A negative full-condition result stops that candidate; no gain/exposure adjustment or additional light paths are appended to rescue it.

No new tone mapper is proposed: existing AgX worsens every full-FG color condition; native AA already averages HDR before clamping. No high-density transport implementation is proposed: the fixed sparse audit found correct and incorrect transitions in equal numbers for legacy display, not a full-frame improvement. No sample-position iteration follows rejected BH. Original source richness is not reduced to meet the renderer.
