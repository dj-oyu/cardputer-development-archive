# Private camera-background resolver: design-only work contract

Version 5, 2026-11-03. Supersedes design-only v1/v2/v3/v4. Resolver fees and hard cap remain fixed. The complete composition/background-only core table and optional canonical-hash reservation now fix the common core cap before implementation/rendering. All listed rates and caps are pre-implementation decisions, never adjustable from subsequent results. No renderer, shadow trace, or production implementation is authorized by this artifact. The existing all-20 geometry/count preflight and frozen roots remain unchanged. This contract proposes a separate host background experiment; original direct, transport, and AA failures remain visible.

## Scope and domains

The active character path stays A2 affine baseline, with floor-reflection OFF. Keep its character coverage, native depth, shaders, and old budgets separately. New full-scene composition selects finite source-floor hits strictly in front of the retained character depth, keeps the character on an exact native-float depth tie, and uses source world radiance on a true floor miss when no retained character wins. Background-only is a separate character-camera-hidden counterfactual, but retains character geometry as shadow occluders.

Runtime retained composition slots Q are 39,555 front and 39,573 oblique: 32,400 centers plus three additional slots per AA target. Selected target centers are overwritten and must not be shaded by the background resolver. The earlier all-center plus all-quarter ordering audit has 41,940/41,964 probes. It is a separate geometry-only preflight, not 41,964 runtime shading calls. The global work cap below conservatively reserves the larger 41,964 geometry-slot bound; unused target-center allowance is explicit over-reservation, not an instruction to execute it. Runtime category/count limits should use the actual per-case Q.

Current composite shading requires combined-empty 29,098/28,902 slots plus two retained front quarter replacements, giving 29,100/28,902 possible floor evaluations. The rear-paw target center is an ordering-audit failure but is overwritten, not a third final replacement. Baseline additions at the two quarters are 48 positive kernels each. Exact all-condition replacement callback counts must be independently captured before physical runs; the coarse 48-per-evaluation guarantee does not depend on them.

On success: Q = KEEP + FLOOR + WORLD; WORLD = exact-parallel + negative-t + outside-finite-floor + source-clip-outside. Nonfinite calculations fail rather than become a miss. Each FLOOR evaluation executes the unchanged 48 sample kernels; only positive geometric kernels invoke visibility. Kernel callbacks are not removed by black rho, zero light energy, or future occlusion. No floor higher-bounce or floor-reflection path is introduced.

## Independent traversal contract

A new cumulative `vis_budget` is dedicated to background shadows only: 2,000,000 rays, 200,000,000 node visits, 100,000,000 triangle tests. The old direct 1M/100M/50M and transport 20M/800M/300M remain separate and unchanged. The original combined-primary-direct 1M failure remains a failed historical constraint, not retrospectively fixed by relabeling it.

One complete background-only frame has at most 39,573 × 48 = 1,899,504 rays, strictly below 2M. Composite coarse maximum is 29,100 × 48 = 1,396,800. This proves the ray count only. Existing owned 1,566-triangle geometry has 1,023 built nodes. The complete-frame brute envelope is 1,943,192,592 node visits and 2,974,623,264 triangle tests. Consequently 200M/100M are actual-run abort gates, not established fits; no adjustment after results.

`vis_segment_occluded` remains unchanged. Its two-sided segment excludes exactly `VIS_SEGMENT_EPSILON=1e-5` at both ray endpoints, rejects length <= 2 epsilon, and does not offset P along the normal. The lighting receiver admission remains the distinct disk-surface `FOX_DISK_ENDPOINT_EPSILON=1e-9`. Visibility failure is never interpreted as visible or black success.

## Work unit and call-site table

A fee is a conservative reservation for the named, bounded source-semantic work at that call site. It is not a machine-instruction count, CPU timing claim, or a traversal-work replacement. Scalar arithmetic/finite checks, branches, fixed-loop control, helper calls, source-level loads/stores, reservation guards, and result/counter bookkeeping are included in the identified categories. libm internals, allocator internals, and compiler expansion are not claimed instruction-bounded by these fees. This is a fresh table, not reuse of the earlier floor-reflection 12,000 allowance.

## Owned descriptor, API, and generations

Suggested opaque API: `fox_bg_scene_build/retain/release/bytes/overlaps`, `fox_bg_binding_set/clear`, `fox_bg_work_init`, `fox_bg_resolve`. `fox_bg_generation` contains existing `vis_generation` plus independent camera/material/emission/illumination tokens. The retained BVH visibility.light may remain its original value across separately built scenario scenes; new lighting lifetime is never forced into that old token. The frame binding retains the scene. `resolve` receives a final event (integer pixel x/y and sample UINT32_MAX for center or 0..3 for exact quarter offsets), character-hit/native-depth, declared mode, work ledger, separate background-shadow budget and output result. There is no retained-final flag and no discarded target-center runtime call. A thin adapter maps the private result to the independent core callback result. Runtime loops only retained final slots; existing preflight owns discarded-center audits.

The descriptor owns camera9 F32, derived exact Q32/t32/inverse/dCamera, source origin/unit view and clip, the four finite source floor vertices/six indices, source rho and Le, prepared direct light data with world zero, and separate source world radiance. It retains the original owned visibility BVH, including character occluders and floor. No borrowed input arrays or new BVH survive build. Result components are direct, rho-world, emission, combined, plus event x/y/sample, selected kind/miss reason/triangle ordinal, character and floor native-float depths, floor hit geometry, snapshot/identity fingerprints, and local query counters. True world misses set only world/combined. Character keep does not reevaluate or alter the old shader output.

Generation mapping is explicit. Existing geometry/pose/light exactly match the retained BVH binding. Floor vertices/indices require geometry increment. Native camera9 or source origin/view/clip require camera increment. Source rho requires material increment, including the albedo condition. Le requires emission increment. Prepared disk values or source world radiance require independent illumination increment, including ambient and direction/intensity conditions. They do not require modifying or rebuilding the old retained visibility scene just to increment visibility.light. Visibility geometry/pose/light still exactly match whichever original owned BVH is bound. Snapshot/identity fingerprint changes invalidate the frame binding; hashes cannot substitute for their field-group generation checks. All tokens nonzero and monotonic; changed owned group with unchanged corresponding token rejects. Retained old generations remain valid until released. Build/rebind failure leaves previous ownership intact. Actual all-20 source hashes, source-camera metadata and field values are pinned externally; generation numbers are caller change tokens, not self-verifying evidence.

Host64 proposed layout, to measure before source freeze: input 752 B; owned scene 976 B; 15-category work 296 B; result 208 B; context (64 B binding, budget pointers, 10 counters, last result, mode) 376 B; VIS budget 48 B. Total new live state about 1,696 B excluding optional caller input 752 B. One old + one new descriptor replacement peak adds 976 B. Existing retained BVH bytes and potentially retained BVH generations are separately itemized. Fixed authorized cap is 16 KiB new-owned state per instance, with two-generation peak separately bounded; no post-result increase. New named call chain must measure <=4 KiB, including unchanged disk evaluator, bridge, and segment function; this is a pending compile/fixture gate, not a current proof.

### Agreed core adapter shapes (design only)

The core worker proposes a 24-byte query: four uint32 fields x/y/sample/character_hit, float character_depth, uint32 mode. Center sample is UINT32_MAX; quarter sample0..3 has the fixed half-pixel-grid offsets used by A2. Mode is fixed by the frame binding; character_hit is exactly0 or1; absent-character query depth is canonically0. The private resolver does not own or modify old character pixels.

The compact core result is 40 bytes: uint32 action, uint32 floor_classification, double floor_native_depth, double linear_rgb[3]. Actions KEEP_CHARACTER=0, FLOOR=1, WORLD=2; classification FLOOR_HIT=1 or SCENE_MISS=2, never UNKNOWN on success. Native floor depth is the exact compared float promoted to double, not an unrounded analytic substitute; SCENE_MISS depth is canonically0. FLOOR_HIT keeps the exact promoted float even for KEEP behind/tied. Both the compact adapter output and full private candidate are completely zero-initialized and committed only on success. KEEP RGB is finite/nonnegative zero and does not replace old character RGB. Full private miss reasons/components remain separate. The existing mode/source case binding is validated once at frame entry; no borrowed per-event light scene is necessary.
